# RAG 知识库问答 — 技术架构说明

> 目标：可在生产环境运行的知识库问答（非 Demo）。  
> 已定调：**知识库私有部署 + 模型走公网 API**（本机不部署大模型）。  
> 约束摘要：日活问答数万级；大量扫描 PDF / 表格 / Word；多租户与文档级权限；团队以 Python 为主。

---

## 1. 产品目标与 SLA

### 1.1 产品形态

| 维度 | 选择 |
|------|------|
| 形态 | 多轮客服 / FAQ 知识库问答，带引用与权限 |
| 存储 | 原文件、向量、权限、审计均在私有环境 |
| 推理 | Embedding / Rerank / LLM 经统一网关调用公网 API |
| 解析 | OCR、表格、Word 在私有异步流水线完成 |

### 1.2 推荐 SLA（私有库 + 公网模型）

| 路径 | 含义 | 目标 |
|------|------|------|
| 快答 | FAQ 高置信直出 / 短证据 | P95 ≤ 2–3s |
| **标准 RAG（主路径）** | 混合检索 + 可选精排 + 公网生成 | **P95 ≤ 3–4s** |
| 首 Token（流式） | 开始吐字 | **TTFT P95 ≤ 1.2s** |
| 拒答 / 无权限 | 不调或极少调模型 | P95 ≤ 1–2s |
| 可用性 | 问答 API | 建议 99.9% |

主 KPI 建议写死：**标准路径 P95 ≤ 4s，TTFT P95 ≤ 1.2s**。体验上优先保证流式首包，而不是一味压总时长。

## 2. 总体架构

```
┌──────────────┐     ┌─────────────────────┐     ┌──────────────────────────┐
│ 文档源/上传   │ ──► │ 解析/切分/向量化      │ ──► │ 私有存储                  │
│ PDF/Word/表  │     │ (异步，可含 OCR)      │     │ 对象存储 + DB + 向量 + 全文 │
└──────────────┘     └─────────────────────┘     └────────────┬─────────────┘
                                                              │ ACL filter
┌──────────────┐     ┌─────────────────────┐                  │
│ 用户 / 渠道   │ ──► │ API 网关             │                  │
│ Web/飞书等    │     │ JWT / 限流 / 租户    │                  │
└──────────────┘     └──────────┬──────────┘                  │
                                ▼                             │
                     ┌─────────────────────┐                  │
                     │ 问答编排 (Python)    │◄─────────────────┘
                     │ ACL → 检索 → 出网闸门 │
                     └──────────┬──────────┘
                                │ 仅 query / 允许出网的 chunk
                                ▼
                     ┌─────────────────────┐     ┌─────────────────┐
                     │ 模型网关 (唯一出网口) │ ──► │ 公网模型 API      │
                     │ embed/rerank/chat   │     │ Embedding/Rerank/LLM │
                     └─────────────────────┘     └─────────────────┘
```

### 分层原则

1. **同步路径要短**：问答热路径不做 OCR；重解析走异步队列。  
2. **检索与生成解耦**：换 Embedding / LLM 不绑死同一进程逻辑。  
3. **原文与向量分离**：向量库存向量 + chunk 元数据；原文在对象存储/业务库，引用可回源。  
4. **控制面独立**：FAQ CRUD、权限、重建索引与问答热路径分离。  
5. **出网唯一口子**：业务代码不直连厂商 Key；一律经模型网关。

## 3. 技术选型（本约束下的推荐基线）

| 域 | 推荐 | 说明 |
|----|------|------|
| API / 编排 | Python + FastAPI + 状态机/轻量编排 | 团队熟悉；可流式 SSE |
| 业务库 | PostgreSQL 或现有 SQLite（演进到 PG） | 用户、ACL、会话、审计 |
| 对象存储 | MinIO / 本地磁盘 | 原文件私有 |
| 向量库 | Qdrant（或 pgvector 中小规模） | payload filter 支持文档 ACL |
| 全文 | OpenSearch / 内存 BM25（小规模） | 与向量做 Hybrid |
| 缓存 | Redis | 会话、限流、可选语义缓存 |
| 解析 | Docling / MinerU + OCR + python-docx / Tika | 扫描 PDF、表格、Word |
| Embedding / Rerank / LLM | 公网 API（如 DashScope） | 经模型网关；本机不跑模型 |
| 观测 | OpenTelemetry + 日志审计 | 一次问答分阶段耗时 |

### 规模直觉（日活数万问答）

- 平均 QPS 不高，峰值按 5–10× 估算即可。  
- 瓶颈常在：**公网模型 RTT + 解析队列**，不是网关本身。  
- **问答与解析资源池隔离**，避免 OCR 拖垮在线问答。

## 4. 文档处理（Ingest）

### 4.1 解析路由

| 类型 | 策略 |
|------|------|
| 扫描 PDF / 复杂版面 | 版面解析 + OCR |
| 表格 | 抽成 Markdown/结构化；按行或「表头+行」切块 |
| Word | 保留标题层级；复杂文档可转 PDF 再走版面链路 |
| 失败 | 质量分 + 重试队列；失败文档默认不对问答可见 |

### 4.2 切分与元数据

- 结构感知切分优先；FAQ 可一问一答一块。  
- 推荐父子块：检索用小块，生成回父段。  
- Chunk 必带：`tenant/user 范围`、`doc_id` / `faq_id`、`visibility`、`owner`、`allow_egress`、`page/section`、版本哈希。

### 4.3 索引生命周期

- 增量：变更 → 删旧 chunk → 写新 chunk。  
- 换 Embedding / 切分策略：双索引或全量重建 + 可回滚。  
- ACL 字段变更后需同步向量 payload（或触发重建）。

---

## 5. 检索与生成

### 5.1 推荐检索链路

1. Query 理解（规则优先；可选公网改写）  
2. **ACL：算出可见文档集合 / 过滤条件（检索前强制生效）**  
3. Hybrid：稠密向量 + BM25 → RRF 融合  
4. Rerank（公网）：仅 `allow_egress=true` 的候选  
5. 上下文组装 + 脱敏 + token 预算  
6. 生成（公网 LLM，流式）或 FAQ 高置信直出  
7. 引用校验、审计落库  

### 5.2 为何必须 Hybrid +（建议）Rerank

- 纯向量：专有名词、型号、错误码易翻车。  
- 纯关键词：语义改写问法易漏。  
- Rerank：用较小 topN 精排，比盲目堆上下文更稳、更省 token。

### 5.3 文档级 ACL（本项目语义）

| 字段 | 含义 |
|------|------|
| `visibility=public` | 任意登录用户可检索 |
| `visibility=private` | 仅 `owner_username` 与 ops 可检索 |
| `allow_egress=true` | 命中后允许送公网 rerank/LLM |
| `allow_egress=false` | 可本地直出标准答，**禁止**把正文送公网模型 |

硬规则：

- **禁止**「先召回再按权限丢掉」作为唯一手段。  
- 向量检索与全文/BM25 **同一套可见性约束**。  
- ops 管理面可见全部；外部挂载（如 Dify）默认只出 `public` 且可出网内容。

## 6. 问答时序（ACL → 检索 → 公网 API）

```
客户端                API                   编排服务                 权限/ACL
  │  POST /chat+JWT    │                      │                      │
  │───────────────────►│ 鉴权/限流/租户         │                      │
  │                    │─────────────────────►│                      │
  │                    │                      │ 解析 principal        │
  │                    │                      │ (user, role)         │
  │                    │                      │─────────────────────►│
  │                    │                      │◄── 可见范围约束        │
  │                    │                      │                      │
  │                    │                      │ ① Query 处理(本地优先) │
  │                    │                      │ ② Embedding→模型网关   │
  │                    │                      │ ③ 私有混合检索+ACL     │
  │                    │                      │ ④ Rerank→网关(可出网块)│
  │                    │                      │ ⑤ 脱敏/出网闸门        │
  │                    │                      │ ⑥ LLM→网关(流式)      │
  │                    │                      │ ⑦ 审计落库            │
  │◄════ SSE ═══════════════════════════════│                      │
```

### 分阶段要点

| 阶段 | 位置 | 是否出网 |
|------|------|----------|
| JWT / 限流 / 会话 | 私有 | 否 |
| ACL 可见范围 | 私有 | 否 |
| Embedding(query) | 网关 → 公网 | **仅用户问题**（一般不含库正文） |
| 向量 + BM25 | 私有 | 否 |
| Rerank | 网关 → 公网 | query + 允许出网的候选文本 |
| LLM 生成 | 网关 → 公网 | 问题 + 脱敏后的 topK 片段 |
| 审计 / 反馈 | 私有 | 否 |

## 7. 出网边界清单

### 7.1 绝对不出网（红线）

- 完整原文件、全量向量库导出、ACL 矩阵、密钥  
- `allow_egress=false` 的文档正文  
- 整库批量送给模型做蒸馏/总结（默认禁止）  
- 解析/OCR/切分/权限计算全过程  

### 7.2 可以出网（须经模型网关 + 审计）

| 用途 | 内容 | 最小化 |
|------|------|--------|
| Embedding | 当前问题（及可选改写） | 不附带知识库正文 |
| Rerank | query + 少量候选 | 条数/长度硬上限 |
| Chat / Intent | 提示词 + 问题 + 允许出网的 chunk | topK 与 max tokens 上限 |

### 7.3 「送外网」≠「用户访问不了」

```
用户浏览器 ──► 你的私有服务（始终可问答）
                    │
                    └──可选──► 公网大模型（「送外网」仅指这一跳）
```

关闭某条 FAQ 的「送公网模型」后：用户仍可提问；系统尽量本地直出标准答，不把该条内容发给模型厂商。

---

## 8. 模型网关职责

1. 托管并轮换 API Key（业务进程不散落密钥）  
2. 统一超时、重试、主备模型降级  
3. 按租户/用户配额与计费打点  
4. 审计：`purpose` / `request_id` / token / 延迟（默认不落全文 prompt）  
5. 阻断超长上下文、无租户、明确禁止出网的内容  

内部调用形态（示意）：

```text
embed_query / embed_documents
rerank(query, documents[])
chat_llm(purpose=chat|intent|...)
```

## 9. 安全、多租户与合规

- 鉴权：`Authorization: Bearer <JWT>`（含 `sub` / `role`）  
- 租户/用户隔离：检索 filter + 会话归属校验  
- 出网前 PII 脱敏（手机号、证件号、邮箱等）  
- 敏感文档 `allow_egress=false`  
- 审计：谁问了什么、命中哪些 doc、是否出网  

> 说明：知识库存私有、模型走公网时，**检索片段会短暂出域**。须与业务/法务确认可接受范围；严格等保隔离场景需改为专有云或自建推理。

## 10. 质量与运维

### 10.1 评测（生产门槛）

- 离线金标：问题 / 应命中文档 / 标准答 / 是否应拒答  
- 指标：Recall@k、引用准确、忠实度、延迟、单次成本  
- 在线：点赞点踩、转人工、抽样 Bad Case  

### 10.2 可观测

一次问答至少拆：ACL、embedding、向量、BM25、rerank、生成、总耗时与 token。

### 10.3 成本控制

- FAQ 高置信直出，少调 LLM  
- 控制 topK 与上下文长度  
- 模型路由（简单/复杂）  
- 租户日配额与告警  

---

## 11. 推进顺序（建议）

1. 解析 → 切分 → Hybrid 检索 → 带引用/直出生成（最小闭环）  
2. ACL + 异步 ingest + 流式 + 观测  
3. 模型网关、脱敏、出网闸门、配额  
4. 评测门禁与索引版本发布  
5. 再考虑 GraphRAG / 多跳 Agent（按需）  

原则：**先把检索正确率与权限/出网边界做扎实，再堆 Agent 复杂度。**

## 12. 与本仓库落地的对应关系（摘要）

当前 ReplyKit 已按本架构收敛的部分包括：

| 架构点 | 代码落点（示意） |
|--------|------------------|
| 模型网关 | `src/model_gateway.py` |
| 出网脱敏 | `src/egress.py` |
| FAQ 文档 ACL | `src/acl.py` + FAQ 表字段 + 检索 filter |
| 混合检索 | `src/retrieve.py` + `src/knowledge.py` |
| 运营配置 ACL | Web「FAQ 管理」表单（可见范围 / 所属用户 / 送公网模型） |
| 配置开关 | `FAQ_ACL_ENABLED`、`MODEL_EGRESS_*`（见 `.env.example`） |

后续可增强：Postgres/多租户 SaaS 化、独立 HTTP 模型网关进程、扫描 PDF 专用解析路由、完整离线评测门禁等。
