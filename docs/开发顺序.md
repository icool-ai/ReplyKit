# ReplyKit — 可实行开发顺序

> 基于当前仓库进度 +《智能客服解决方案》  
> 原则：**先答得准 → 再流程化 → 再可接入 → 最后运营化**，每阶段有验收标准，做完再进下一阶段。

---

## 〇、现在已经完成（不必再排期）

| 项 | 状态 |
|----|------|
| 通义 LLM + Embedding + 本地 Qdrant RAG | ✅ |
| FAQ（txt/md）+ 操作文档（docx）入库 | ✅ |
| 相似度分数打印 + SCORE_THRESHOLD 过滤 | ✅ |
| 闲聊白名单（跳过检索） | ✅ |
| 关键词转人工 | ✅ |
| docx 抽图 → 章节绑定 → 画廊展示 | ✅ |
| FastAPI + Vue 前端（`web/`）本地调试 | ✅ |

**当前水平：** RAG 演示 / 初级 MVP 骨架。

---

## 总路线（建议 4 个阶段）

```
P0 答得更准（结构化 FAQ + 澄清）
 → P1 对话更可用（欢迎语/敏感词/会话上下文 + 1 条多轮）
 → P2 能接业务（简单 API + 工具调用查订单等）
 → P3 能运营（日志指标 + 知识管理最小后台）
```

后面的「SaaS 全控制台 / 热线语音 / 多租户」放到 **P4+ 可选**，不要穿插进前三阶段。

---

## P0：答得更准（约 3–5 天）

**目标：** 「你好」不乱检；业务问能直出；模糊问能澄清；少胡编。

### 任务顺序

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P0-1 | 结构化 FAQ | 把 `data/faq` 改成「标准问 + 相似问 + 答案」格式（JSON/YAML 或约定 txt） | 一条 FAQ 对应一条向量（或标准问+相似问向量，答案在 payload） | ✅ 已完成：`data/faq/faq.json` |
| P0-2 | 直出 / 澄清双阈值 | 配置 `DIRECT_THRESHOLD`、`CLARIFY_THRESHOLD`；高分直出答案，中分返回 Top-N 候选问用户点选 | 「退货几天」高分直接答；模糊问出现澄清列表 | ✅ 已完成（点选 UI 留待 P1-2） |
| P0-3 | FAQ 优先于长文档 | 检索只查 FAQ，不再走操作手册 | 问政策优先命中 FAQ | ✅ 已完成：`search_faq`（仅 FAQ） |
| P0-4 | 欢迎语 / 无答案 / 敏感词可配置 | 从 `.env` 或 `data/bot_config.json` 读取话术 | 改配置重启即生效，无需改代码 | ✅ 已完成：`data/bot_config.json` |
| P0-5 | 回归用例表 | 维护 20 条测试问法（闲聊 / FAQ / 手册 / 转人工 / 拒识） | 每次改检索策略跑一遍，通过率可记录 | ✅ 已完成：`data/regression_cases.json` + `uv run python -m src.regression` |

### 本阶段不要做

多轮对话工厂、表格问答、OpenAPI、管理后台。

### 完成标志

- [x] 闲聊不进知识库  
- [x] FAQ 有明确直出路径（可不必每次 LLM 改写答案）  
- [x] 低分不答，中分澄清，高分直出  
- [x] 20 条用例里 FAQ/手册主路径 ≥ 80% 合理（用回归脚本验收）

## P1：对话更可用（约 4–7 天）

**目标：** 像「客服机器人」而不只是「搜文档」。

### 任务顺序

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P1-1 | 会话上下文 | API/前端把最近 N 轮 history 传给 bot；追问用 last_topic 拼接或短改写后再检索 | 「那个怎么弄」能结合上一轮「门禁」理解 | ✅ 已完成：`src/context.py` + session 历史 |
| P1-2 | 澄清点击续聊 | 澄清列表可点选，点选后当作标准问再答 | UI 上能点候选问，不必手打 | ✅ 已完成：`web/` 澄清按钮 + API `clarify_options` |
| P1-3 | 转人工规则增强 | 连续无答案 N 次 / 重复提问 N 次 → 转人工 | 故意问 3 次无关问题会提示转人工 | ✅ 已完成：`handoff_after_no_answer` / `handoff_after_repeat` |
| P1-4 | 第一条多轮流程（规则版） | 选 1 个高频流程（如「访客预约」或「查订单」），用状态机/简单节点，不必上完整对话工厂 | 能走完：问意图 → 要槽位 → 给结果（可先 mock） | ✅ 已完成：`src/flow_order.py` 查订单 |
| P1-5 | 意图粗分类（可选） | 规则或小模型：闲聊 / FAQ / 手册 / 任务 / 转人工 | 终端能打印 `intent=...`，路由正确率肉眼可接受 |

### 本阶段不要做

完整 LGF、实体管理系统、渠道对接。

### 完成标志

- [x] 有上下文的追问不翻车  
- [x] 至少 1 条多轮主路径跑通  
- [x] 转人工不止关键词一种触发  

---

## P2：能接业务（约 5–8 天）

**目标：** 从 Demo 变成「可被别的系统调用」的服务。

### 任务顺序

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P2-1 | HTTP API | FastAPI：`POST /chat`（session_id, message）→ answer + sources + images | Postman/curl/Vue 能调通，共用同一套 bot | ✅ 已完成：`src/api.py` + `/assets`；`uv run replykit` |
| P2-2 | 会话存储 | 内存或 SQLite 存 session 历史 | 重启前同 session_id 能续聊（SQLite 可持久） | ✅ 已完成：`SqliteSessionStore` → `data/sessions.db` |
| P2-3 | 工具调用（1～2 个） | 查订单 / 创建工单（先 mock API，再换真接口） | 用户说订单号能返回 mock 物流状态 | ✅ 已完成：`orders`/`tickets` → `data/business.db`；对话可创建工单 |
| P2-4 | 图片 URL 化 | API 返回图片相对路径或静态文件服务 `/assets/...` | 前端/Postman 能打开配图链接 | ✅ 已完成：`paths_to_asset_urls` + `StaticFiles(/assets)`；`/chat` 返回绝对配图 URL |
| P2-5 | 简易鉴权 | API Key 或固定 Token | 无 Token 拒绝访问 | ✅ 已完成：`API_KEY` + `X-API-Key` / `Bearer`；`/health`、`/assets` 放行 |

### 本阶段不要做

微信完整接入、呼叫中心、权限角色体系。

### 完成标志

- [x] 外部系统只调 API 即可问答  
- [x] 至少 1 个业务工具真实或 mock 闭环  
- [x] Vue 前端（`web/`）作对话调试与 FAQ 管理  

---

## P3：能运营（约 5–10 天）

**目标：** 知道「哪里答不好」，并能改知识，而不用改代码。

### 任务顺序

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P3-1 | 对话日志 | 每次问答落库：问、答、分数、来源、是否转人工 | 能导出最近 100 条 | ✅ 已完成：`src/chat_log.py` → `data/chat_logs.db`；`uv run python -m src.chat_log` |
| P3-2 | 基础指标 | 未命中率、转人工率、Top 未识别问法 | 页面或脚本每周能看一眼 | ✅ 已完成：`GET /metrics`（`src/metrics.py` 注册表可扩展） |
| P3-3 | FAQ 最小管理 | 增删改 FAQ + 一键重建索引（可先做 CLI，再做简单 Web） | 运营改一条 FAQ 后重建即可生效 | ✅ 已完成：`faqs.db` + `POST /faqs*`；增删改增量同步向量；`/faqs/rebuild` 全量兜底 |
| P3-4 | 敏感词表外置 | SQLite `sensitive.db` + `POST /sensitive-words*`；示例 `data/sensitive.txt` 可 import | 加词后命中走敏感词话术（热更新） | ✅ 已完成：启动不自动导入；`SENSITIVE_DB_PATH` |
| P3-5 | 测试/正式两套配置（轻量） | `.env.test` / `.env.prod` 或两个 collection | 改测试库不影响「正式」演示库 |

### 本阶段不要做

完整发布中心、聚类标注平台、多业务空间。

### 完成标志

- [x] 能从日志发现「总答不上的问题」并补进 FAQ（`GET /metrics` → `top_unrecognized`）  
- [x] 非开发人员（或你自己换角色）能改知识（`POST /faqs*` + 增量同步）

## P4+：可选增强（有明确需求再做）

按需挑选，**不要提前全部开干**：

| 项 | 何时做 |
|----|--------|
| OCR 入库 | 手册大量依赖截图内文字、且正文写不全时 |
| 表格问答 | 有价目表/房源表等结构化表要「按条件问」时 |
| 微信 / 企微渠道 | 有现成渠道要接客服时 |
| 坐席辅助推荐 |   |
| 完整对话工厂 + LGF | 多轮流程超过 3～5 条、配置化需求强时 |
| 热线 ASR/TTS | 有呼叫中心需求时 |
| 多租户 / 角色权限 | 多团队共用同一套平台时 |

## 每周节奏建议（可实行）

以 **一人兼职开发** 为例：

| 周次 | 焦点 | 周末交付物 |
|------|------|------------|
| 第 1 周 | P0-1～P0-3 | 结构化 FAQ + 双阈值 + 用例表初版 |
| 第 2 周 | P0-4～P1-2 | 话术配置 + 上下文 + 澄清点选 |
| 第 3 周 | P1-3～P1-4 | 转人工增强 + 1 条多轮 |
| 第 4 周 | P2-1～P2-3 | Chat API + 会话 + 1 个工具 |
| 第 5～6 周 | P3 | 日志指标 + FAQ 管理最小闭环 |

若时间紧：**只做完 P0 + P2-1**，也比摊薄做很多半成品更有用。

## 每阶段开工检查清单（PDCA）

**Plan**

- [ ] 本阶段目标一句话写清  
- [ ] 验收标准可测（见上表）  
- [ ] 明确「本阶段不做」  

**Do**

- [ ] 按表序号做，不跳着加需求  
- [ ] 改检索/话术后跑回归用例  

**Check**

- [ ] 终端日志：分数、意图、配图是否符合预期  
- [ ] 用例通过率是否达标  

**Act**

- [ ] 把阈值、话术、FAQ 格式沉淀成文档/配置  
- [ ] 再开下一阶段  

---

## 推荐的「下一项就做」

结合你现在的代码，**下一个最值得做的是 P0-1 + P0-2**：

1. FAQ 结构化（标准问 / 相似问 / 答案）  
2. 直出阈值 + 澄清阈值（替代「过线就整段塞给 LLM」）

这两项对「问操作文档 / 问政策」的体感提升最大，且不依赖渠道和后台。

## 一句话

先把 **P0（答准）** 做透，再 **P1（能聊）**、**P2（能接入）**、**P3（能运营）**；完整方案里的平台能力放到有真实用户或渠道需求后再开。
